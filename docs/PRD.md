# PRD — Портал приглашений на мероприятия

**Версия:** 0.3 (черновик)
**Дата:** 28.05.2026
**Статус:** прототип фронтенда готов, бэкенд не реализован
**Авторы:** —

---

## 1. Обзор

Портал для создания цифровых приглашений на разные мероприятия. Пользователь (хост) выбирает тип события, собирает страницу-приглашение из блоков, оформляет её визуальным шаблоном и делится ссылкой с гостями. Гости открывают живую страницу, подтверждают участие через форму ответа и бронируют подарки из вишлиста. Хост видит ответы в личном дашборде.

Это **модель живой страницы-приглашения** (как WedWed, Partiful, Paperless Post), а не редактор статичной открытки на печать (как SUPA/Canva). Ключевое отличие: результат — интерактивная страница по ссылке со сбором ответов, а не файл-картинка.

---

## 2. Проблема и цель

Подготовка мероприятия требует: разослать приглашения, собрать подтверждения, согласовать подарки, держать гостей в курсе деталей (место, программа). Сегодня это разрозненно — мессенджеры, бумага, таблицы, ручной подсчёт.

**Цель продукта:** дать хосту один инструмент, где приглашение, RSVP-трекинг и вишлист живут вместе, а гостю — простой способ ответить и не задарить дублирующимся подарком.

---

## 3. Целевая аудитория

- **Хост** — человек, организующий личное событие (свадьба, день рождения, юбилей, baby shower, новоселье) или небольшой корпоратив. Не дизайнер, хочет красиво и быстро.
- **Гость** — получатель ссылки. Открывает с телефона, отвечает за 30 секунд, при желании бронирует подарок.

---

## 4. Типы мероприятий

Портал заточен под несколько поводов; при выборе типа подставляется подходящий набор блоков и тема оформления.

| Тип | Тема по умолчанию | Стартовые блоки |
|---|---|---|
| Свадьба | Романтика | Заголовок, Текст, Локация, Программа, Вишлист, RSVP |
| День рождения | Морская | Заголовок, Отсчёт, Локация, Вишлист, RSVP |
| Детский праздник | Праздник | Заголовок, Текст, Локация, Программа, RSVP |
| Юбилей | Полночь | Заголовок, Отсчёт, Текст, Локация, RSVP |
| Baby Shower | Ботаника | Заголовок, Текст, Локация, Вишлист, RSVP |
| Новоселье | Ботаника | Заголовок, Локация, Программа, RSVP |
| Корпоратив | Полночь | Заголовок, Отсчёт, Локация, Программа, RSVP |

Тип определяет пресет, но любой блок и любую тему можно сменить вручную.

## 5. Функциональные требования

### 5.1 Конструктор приглашения

- Стартовый экран — выбор типа мероприятия плиткой.
- После выбора открывается конструктор с предзаполненными блоками-заглушками.
- Блоки добавляются, удаляются, меняются местами (вверх/вниз).
- Редактирование «по месту» — текст правится прямо на странице.
- Три режима: **Редактор** → **Просмотр** (как видит гость) → **Ответы** (дашборд хоста).

### 5.2 Блоки

| Блок | Назначение | Поля |
|---|---|---|
| Заголовок | Шапка приглашения | Подзаголовок, название, дата, время; мотив-символ и шрифт темы |
| Отсчёт | Живой таймер до события | Подпись, целевые дата-время; тикает в реальном времени |
| Текст | Произвольное обращение | Заголовок абзаца, тело |
| Локация | Место проведения | Название, адрес, заметка, кнопка «Открыть на карте» |
| Программа | Расписание дня | Список пунктов: время + название |
| Вишлист | Список подарков | См. 5.3 |
| Форма ответа (RSVP) | Сбор подтверждений | См. 5.4 |

### 5.3 Вишлист

Каждый подарок — карточка со следующими возможностями:

- **Фото** подарка (по URL) либо иконка-заглушка.
- **Цена** (в тенге) и **ссылка «где купить»** на товар.
- **Бронирование по имени:** гость нажимает «Забронировать», вводит имя — позиция помечается «Забронировал(а): Имя», с возможностью отменить. Защищает от дублирующихся подарков.
- **Групповой подарок (скидываемся):** вместо брони — прогресс-бар сбора суммы. Гости вносят свои суммы, шкала заполняется до цели с процентом.

### 5.4 Форма ответа (RSVP) и трекинг

**Форма для гостя:**
- Имя.
- Выбор «Буду 🎉 / Не смогу».
- **Сопровождающие по именам** (+1, +2…) — кнопка «Добавить гостя», каждый с именем.
- **Ограничения по еде** — отдельное поле (аллергии, вегетарианство и т.п.).
- Свободное поле пожеланий.
- Дедлайн ответа задаётся хостом.

**Дашборд хоста (вкладка «Ответы»):**
- Сводная статистика: придут / гостей всего (с учётом сопровождающих) / не смогут.
- **Фильтры:** Все / Придут / Не смогут — со счётчиками.
- **Поиск** по имени (включая имена сопровождающих).
- Карточка ответа показывает: статус, сопровождающих, пометку по еде, пожелания.
- **Экспорт в CSV** (с корректной кириллицей для Excel): имя, статус, число гостей, сопровождающие, ограничения по еде, пожелания.

### 5.5 Визуальное оформление (шаблоны)

- **10 визуальных шаблонов:** Романтика, Полночь, Ботаника, Морская, Праздник, Нуар, Лаванда, Изумруд, Коралл, Минимал. Светлые и тёмные, тёплые и холодные.
- Каждый шаблон несёт не только палитру, но и:
  - **декоративный фон** (узор: цветовые пятна, сетка, штриховка, конфетти-точки, концентрические круги или чистый фон);
  - **собственный display-шрифт** для заголовков;
  - **мотив-символ** в шапке (❦ ✦ ❧ ≈ ✺ ◆ ✿ ✣ ❀ —).
- Выбор темы — панель карточек-превью (узор + мотив + палитра + название своим шрифтом).
- Селектор шрифта: «Шрифт темы» по умолчанию, с переопределением на Serif / Sans / Mono.

## 6. Нефункциональные требования

- **Мобайл-фёрст:** гости открывают с телефона; страница и формы адаптивны.
- **Скорость заполнения формы гостем:** ориентир — до 30 секунд.
- **Без рекламы** в приглашениях.
- **Приватность:** ответы видны только хосту.
- **Доступность:** контраст текста, читаемые размеры шрифтов.

---

## 7. Текущее состояние прототипа

Реализован фронтенд-прототип (React): выбор типа события, конструктор блоков, три режима, расширенный вишлист, RSVP с трекингом и CSV-экспортом, 10 визуальных шаблонов.

**Известное ограничение:** данные (ответы, брони, суммы сбора) живут только в памяти сессии — это ограничение среды предпросмотра. Для реального продукта нужен бэкенд (см. раздел 8).

---

## 8. Что требуется для продакшена (вне прототипа)

Эти пункты не реализованы и формируют следующий этап:

- **Бэкенд и БД.** Хранение приглашений, ответов, броней и сумм сбора. Кандидат — Supabase/Firebase.
- **Уникальные ссылки.** Генерация адреса вида `site.ru/i/abc123`; гость по ссылке видит ту же страницу, брони и счётчики синхронны между гостями.
- **Аккаунт хоста.** Сохранение приглашений, доступ к дашборду между сессиями.
- **Рассылка.** Отправка ссылки гостям (email/SMS/мессенджер) и напоминания не ответившим.
- **Интерактивная карта** с меткой в блоке локации (сейчас — ссылка на внешнюю карту по адресу).
- **Фото-обложка** в заголовке (загрузка изображения, а не только URL).

Предлагаемая схема данных (черновик):

```
invitations
  id, host_id, event_type, theme, font, slug, created_at
blocks
  id, invitation_id, type, position, data (jsonb)
rsvp_responses
  id, invitation_id, name, attending, companions (jsonb), diet, note, created_at
wishlist_reservations
  id, block_item_id, taken_by            -- одиночная бронь
wishlist_contributions
  id, block_item_id, contributor, amount -- групповой сбор
```

| Partiful | Живая страница, казуальные события | Лёгкий мобильный UX, простой RSVP |

## 10. Метрики успеха (предлагаемые)

- Доля приглашений, доведённых от старта до публикации ссылки.
- Среднее число ответов на одно приглашение / доля ответивших гостей.
- Доля приглашений с заполненным вишлистом и RSVP.
- Возвраты хоста в дашборд.
